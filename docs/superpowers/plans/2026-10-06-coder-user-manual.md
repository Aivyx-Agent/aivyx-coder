# aivyx-coder User Manual Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A three-part manual for aivyx-coder — guide, reference, developer — under `docs/manual/`, accurate to v0.4.5, with the 2,340-line README trimmed to an overview + quick start that points into it and no content lost.

**Architecture:** Markdown chapters `docs/manual/{guide,reference,developer}/NN-name.md`, one `# Title` each, indexed by `docs/manual/README.md`. Content is moved out of README.md (checked against the code as it moves) rather than rewritten from scratch. Drift checks: a test in `crates/aivyx` fails if a CLI flag lacks a heading in the command-line reference; a test in `aivyx-core` fails if a slash command lacks one. The configuration and tools references are generated by scripts (`scripts/gen-config-reference.py`, `scripts/gen-tools-reference.py`), adapted from aivyx-pa's.

**Tech Stack:** Markdown; Rust tests (`aivyx`, `aivyx-core`); Python 3 stdlib scripts.

Spec: `aivyx-ecosystem/docs/superpowers/specs/2026-10-06-user-manuals-design.md` §2.

## Global Constraints

- Every statement checked against the current code (`Cli` in `crates/aivyx/src/main.rs`, `COMMANDS` in `crates/aivyx-core/src/commands.rs`, `Settings` in `crates/aivyx-config/src/lib.rs`, tool `definition()`s, the gate in `aivyx-sandbox`) — not against README text, which may have drifted.
- Part 1 (Guide): everyday users, task-based, plain words. Part 2 (Reference): exhaustive, terse. Part 3 (Developer): contributors.
- Brand voice: warm, precise, direct; short sentences. Licence: BUSL-1.1, "source-available" — never "open source".
- Links between manual pages are relative `.md`; links to repo files elsewhere use `https://github.com/Aivyx-Agent/aivyx-coder/blob/main/<path>`. Never link private repos (aivyx-ecosystem, aivyx-website, aivyx-brand, aivyx-hub, aivyx-wallpapers, aivyx-kitchen).
- The binary is `aivyx-coder`; the crate/package is `aivyx` (unrelated to aivyx-pa's `aivyx` crates).
- README: no content lost — every README section maps to a manual page (Task 6 checks the map).
- Commits: `git commit -s`, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; branch `docs/user-manual`.
- `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings` stay green.

### Task 1: Index, command-line and slash-command references, drift tests

**Files:** Create `docs/manual/README.md`, `docs/manual/reference/01-command-line.md`, `docs/manual/reference/02-slash-commands.md`; modify `crates/aivyx/src/main.rs` (test), `crates/aivyx-core/src/commands.rs` (test).

- [ ] **Step 1: Failing tests.** In `main.rs`'s `#[cfg(test)] mod tests`:

```rust
#[test]
fn every_flag_has_a_command_line_reference_heading() {
    use clap::CommandFactory;
    let manual = include_str!("../../../docs/manual/reference/01-command-line.md");
    let missing: Vec<String> = Cli::command()
        .get_arguments()
        .filter_map(|a| a.get_long())
        .map(|l| format!("--{l}"))
        .filter(|f| !manual.contains(&format!("### `{f}")))
        .collect();
    assert!(missing.is_empty(), "docs/manual/reference/01-command-line.md has no heading for: {missing:?}");
}
```

  In `commands.rs` (add a `#[cfg(test)] mod` if none exists):

```rust
#[test]
fn every_command_has_a_slash_command_reference_heading() {
    let manual = include_str!("../../../docs/manual/reference/02-slash-commands.md");
    let missing: Vec<&str> = COMMANDS
        .iter()
        .map(|c| c.name)
        .filter(|name| !manual.contains(&format!("### `{name}")))
        .collect();
    assert!(missing.is_empty(), "docs/manual/reference/02-slash-commands.md has no heading for: {missing:?}");
}
```
