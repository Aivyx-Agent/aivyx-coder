# aivyx-coder editor integration audit (ACP mode and registry entry), 2026-10-31

Task 11b of Chapter H. A security, correctness and protocol-conformance review
of `aivyx-coder --acp` (crate `crates/aivyx-acp`, `agent-client-protocol`
2.0.0 / schema 1.5.0) and of the ACP registry entry Zed users install it
from. It reports and proves findings; it fixes nothing.

## Scope

- aivyx-coder `main` at `3a52f20` (v0.6.4 plus the Task 13 audit fixes:
  C5/C6 escaping, C22 cancel-while-waiting, C23 start-up notice). Code:
  `crates/aivyx-acp/src/{session,prompter,translate,commands}.rs`, the
  `--acp` branch and signal handling in `crates/aivyx/src/main.rs`,
  `agent_builder.rs`, the child-process code in `aivyx-tools`.
- The registry entry `docs/registry-submission/aivyx-coder/agent.json`
  (identical to the fork `Aivyx-Agent/registry`, branch `add-aivyx-coder`,
  PR 620 head `6828a19`), the v0.6.4 release archives, and the registry's own
  schema, CI and hourly auto-updater (`agentclientprotocol/registry` `main`).
- The client side, by reading Zed's current source (`crates/agent_servers`,
  `crates/util/src/process.rs`, `crates/agent_ui/src/message_editor.rs`),
  because that is what decides how coder is started, stopped and fed.
- Not re-reported: C1–C25 of `docs/audits/2026-10-28-code-audit.md`. C5, C22
  and C23 were re-checked where ACP touches them (see "Checked and clean").

## Method

- Ranks as in the other H2 audits: Critical, High, Medium, Low. Every Medium
  is shown real by a failing test or a recorded reproduction.
- Proofs ran in a fresh clone (`/tmp/claude-1000/acp-audit/coder`, own
  `CARGO_TARGET_DIR`), never in the working checkout. The live probes are an
  integration test, `crates/aivyx/tests/acp_audit.rs` (full text in the
  appendix), that starts the real `aivyx-coder --acp` binary **in its own
  process group, as Zed does**, and speaks raw newline-delimited JSON-RPC to
  it, against a wiremock OpenAI-compatible model server, with `HOME` and the
  XDG directories pointed at temporary directories. One unit probe sits in
  `aivyx-acp/src/translate.rs`. Every `audit_` probe fails on current code
  (that is the proof); every `check_` probe passes. Final run: 6 audit probes
  failed, the stdin-EOF control and 5 checks passed; `aivyx-acp` lib: 83
  passed, the 1 audit probe failed.
- Every message the probes read from coder's stdout was parsed as JSON; a
  non-JSON line would have failed the test. None appeared.
- Command payloads were `sleep 29x`, `true` and `touch` of a marker under
  `/tmp/claude-1000/`; all leftover processes were killed by the tests.
- Registry: archives downloaded and hashed; the bot's version bump simulated
  in a scratch clone of the registry and checked with the registry's own
  `verify_agents.py --auth-check` (one run; a second run was refused by the
  session's permission policy, so the exit-code part is from reading the
  script, quoted below).
- No live Zed session: driving the Zed GUI was not possible from this
  session, so the headless JSON-RPC driver stands in for it, and Zed's
  behaviour is taken from its source. `~/.config/zed` was not touched.

## Findings

### A1 (Medium) Closing the agent in Zed leaves coder's running commands alive

- **Where:** `crates/aivyx-tools/src/process.rs:62` and `:225`
  (`command.process_group(0)` for every confined command: `run_shell`,
  `run_command`, `/test`, the progress check), with no parent-death link; and
  `crates/aivyx/src/main.rs:752` (the SIGTERM path removes only the headless
  temp directory).
- **What happens:** Zed starts an agent server in a new session
  (`util::process::Child::spawn` → `set_pre_exec_to_start_new_session`) and
  stops it from `impl Drop for OwnedChild` (`agent_servers/src/acp/transport.rs`)
  with `libc::killpg(pid, SIGKILL)` (`util/src/process.rs:116`). That kills
  coder's group only. Every command coder runs leads its own process group
  (deliberately, so a tool call can kill its own tree), so SIGKILL of the
  agent's group never reaches it, and SIGKILL cannot be caught to clean up.
  A dev server, `cargo watch`, a long test run or a looping test binary the
  user approved keeps running after they close the thread or quit Zed, holding
  ports, CPU and files. The confiner's private `aivyx-confine-XXXXXX` temp
  directory leaks too. Even a plain SIGTERM (which does kill the commands)
  leaves that directory: `remove_headless_temp_dir` only knows the headless
  directory, so C7's fix does not cover ACP.
- **Proof:** `audit_a1_editor_kill_leaves_no_command_running`: approve a
  `run_shell` `sleep 291`, then `kill -KILL -- -<coder pgid>`, wait 1 s:
  `still running after the editor killed the agent's group: ["2951841"]`.
  `audit_a1_sigterm_kills_the_command_and_cleans_tmp` (`TMPDIR` = empty dir,
  SIGTERM to coder): the `sleep` is gone, but
  `temp entries left after SIGTERM: ["aivyx-confine-3Wi57m"]`. Control
  `audit_a1_control_stdin_eof_ends_the_command` passes: when the editor only
  closes stdin, coder exits and the command dies.
- **Fix direction:** have each confined child's group leader die with coder:
  `prctl(PR_SET_PDEATHSIG, SIGKILL)` in the confiner's `pre_exec` (Linux),
  plus a check that the parent is still the expected pid right after it, so a
  command's own tree goes when its leader does (the existing `ProcessGroup`
  kill on drop covers the rest while coder is alive). Alternatively a small
  watchdog that holds a pipe to coder and `killpg`s the registered groups on
  EOF. In the SIGTERM/SIGHUP handler, also remove the confiner's temp
  directories (the same registry idea as `kill_all_process_groups`). On macOS
  (`NoopConfiner`) there is no PDEATHSIG; the watchdog form covers both.

### A2 (Medium) An @-mentioned file in Zed never reaches the model

- **Where:** `crates/aivyx-acp/src/session.rs:271` (`extract_prompt_text`
  keeps only `ContentBlock::Text`), with `AgentCapabilities::new()` at `:596`
  (no `embeddedContext`).
- **What happens:** the spec makes `ResourceLink` baseline content ("All
  agents MUST support resource links in prompts", schema `content.rs:54`).
  Zed's message editor sends an @-mentioned file as a `ResourceLink` whenever
  the agent does not advertise `embeddedContext` (`mention_to_content_block`,
  `message_editor.rs`), which is coder's case, and offers only File and
  Symbol mentions to such an agent. coder drops the block and appends
  "(non-text content in this message was not forwarded)". A Zed user who
  writes "Explain @main.rs" sends the model "Explain " and that note: the
  primary way to point the agent at code in Zed silently does nothing, and the
  model has to guess. Symbol mentions are lost the same way.
- **Proof:** `audit_a2_a_resource_link_reaches_the_model`. Exchange:
  ```
  -> {"jsonrpc":"2.0","id":3,"method":"session/prompt","params":{"sessionId":"<sid>","prompt":[
       {"type":"text","text":"Explain "},
       {"type":"resource_link","name":"main.rs","uri":"file:///tmp/.tmpXXXX/src/main.rs"}]}}
  model received: {"role":"user","content":"Explain \n(non-text content in this message was not forwarded)"}
  ```
  The existing unit test `non_text_block_is_dropped_with_a_trailing_note`
  pins the current behaviour.
- **Fix direction:** render a `ResourceLink` into the prompt text as a
  reference (name, the path for a `file://` URI, line range if Zed puts one in
  the fragment) and let the model open it with `read_file`, so `deny_paths`,
  `read_only_paths` and the outside-project note still apply. Do not read the
  linked file directly in the ACP layer: that would be an unconfined read path
  around the gate. Only then consider `embeddedContext` (and treat embedded
  text as untrusted input through the injection scan).

### A3 (Medium) The registry auto-updater will break the Zed install on the first release after PR 620 merges

- **Where:** `docs/registry-submission/aivyx-coder/agent.json:14` and `:20`
  (`"cmd": "./aivyx-coder-v0.6.4-<target>/aivyx-coder"`), produced by
  `.github/workflows/release.yml:55`
  (`STAGE_NAME="aivyx-coder-${GITHUB_REF_NAME}-..."`, the archive's top
  directory carries the version).
- **What happens:** once listed, the registry's hourly `update-versions.yml`
  bumps every agent with a GitHub `repository`. For binary entries,
  `update_versions.py` (lines ~505–545) rewrites `version`, each `archive` URL
  and `sha256`, and leaves `cmd` untouched ("existing `cmd`/`args`"). After
  coder v0.6.5 ships, the entry would point at the v0.6.5 archive while `cmd`
  still names `aivyx-coder-v0.6.4-.../aivyx-coder`, a path not in that
  archive. The bot's safety net does not catch it: in `--auth-check` a binary
  whose `cmd` is not found comes back from `prepare_binary` as **skipped**
  (`verify_agents.py:770`, `skipped=True`), skipped results are not failures
  (`:1133–1146`), and the run ends "All tests passed!" with exit 0, so the bad
  bump is committed and every Zed user's install fails until someone sends a
  manual PR. coder's release routine (CLAUDE.md step 4) only updates the
  fork branch, which no longer matters once the PR is merged.
- **Proof (simulation):** in a scratch registry clone, the entry as the bot
  would write it for v0.6.3 (version, URLs and v0.6.3 sha256s changed, `cmd`
  unchanged) through the registry's own verifier:
  ```
  $ python3 .github/workflows/verify_agents.py --auth-check --agent aivyx-coder
  [1/1] aivyx-coder (binary)
    → Verifying SHA-256...
    ⊘ Skipped: Executable not found: aivyx-coder-v0.6.4-x86_64-linux-musl/aivyx-coder
  Summary  Passed: 0  Failed: 0  Skipped: 1
  All tests passed!
  ```
  Other agents with a versioned directory in `cmd` (`cortex-code`) have no
  GitHub repository and so are not auto-bumped.
- **Fix direction:** make the archive layout version-free before the PR
  merges, e.g. a top directory `aivyx-coder-<target>/` or the binary at the
  archive root, and `cmd` to match; keep the versioned archive *file* name
  (the bot rewrites that). Add the registry entry on upstream `main` to the
  release routine as a check after merge.

### A4 (Low) `initialize` echoes any protocol version and omits `agentInfo`

- **Where:** `crates/aivyx-acp/src/session.rs:595` and `:415`
  (`InitializeResponse::new(req.protocol_version)`).
- **What happens:** the response must carry the client's version if the agent
  supports it, else the agent's latest. coder echoes whatever arrives, so a
  client offering version 7 is told coder speaks 7 and will not disconnect.
  `agentInfo` (name, version; "will be required") is not sent, so a client
  cannot show which coder build it is running.
- **Proof:** `audit_a4_initialize_answers_a_supported_protocol_version`:
  ```
  -> {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":7,...}}
  <- {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":7,"agentCapabilities":{...},"authMethods":[...]}}
  ```
- **Fix direction:** answer `min(requested, ProtocolVersion::V1)` (V1 for
  anything else), and set `agent_info` with the crate version.

### A5 (Low) Session and mode ids are not checked; requests before `initialize` are served

- **Where:** `session.rs:444` (`run_prompt` uses the one session whatever
  `req.session_id` says), `:683–691` (`set_mode`: any session id; any
  `modeId` other than `plan` silently means `code`), `:695` (`session/cancel`
  ignores the id), and no initialize-first gate.
- **What happens:** a prompt for a session id this process never issued runs
  in the real session; `set_mode` with `modeId: "bogus"` answers success and
  switches plan mode off. With one session per process and a trusted editor
  this is not exploitable, but a client bug (stale id after a restart, a typo
  in a mode id) is masked instead of reported, and turning plan mode off on an
  unknown id is the wrong default.
- **Proof:** `audit_a5_unknown_session_and_mode_ids_are_rejected`:
  ```
  -> {"id":3,"method":"session/prompt","params":{"sessionId":"not-a-session","prompt":[{"type":"text","text":"hi"}]}}
  <- {"id":3,"result":{"stopReason":"end_turn"}}
  -> {"id":4,"method":"session/set_mode","params":{"sessionId":"not-a-session","modeId":"bogus"}}
  <- {"id":4,"result":{}}
  ```
  `check_malformed_and_unknown_messages`: `session/new` sent with no
  `initialize` first succeeds.
- **Fix direction:** reject an unknown session id and an unknown mode id with
  `invalid_params`; optionally refuse session methods before `initialize`.

### A6 (Low) The permission request names a tool call the editor never saw

- **Where:** `crates/aivyx-acp/src/prompter.rs:252`
  (`let call_id = uuid::Uuid::new_v4()`; `PermissionRequest` carries no call
  id).
- **What happens:** coder first reports the call as `tool_call` with the
  model's id, then asks permission with a `ToolCallUpdate` under a fresh UUID,
  and completes the original id. Zed treats a permission subject with an
  unknown id as a new tool call (its test
  `v2_permission_sdk_preserves_requests_and_returns_offered_outcomes`: "the
  tool call subject creates the tool call"), so the thread shows two entries
  per gated call: the real one, and an approval entry that is moved to
  in-progress on Allow and never completed by any later update. Display only;
  the approval itself is bound to the gate's exact target.
- **Proof:** `audit_a3_permission_request_names_the_reported_tool_call`
  (probe name predates the renumbering):
  ```
  tool_call ids: ["call_touch"]
  permission toolCallIds: ["e4bb4a9f-9390-4241-9641-07b56d4223bc"]
  updates: [("call_touch", "completed")]
  ```
- **Fix direction:** carry the `ToolCallId` into `PermissionRequest` (or a
  task-local set by `ToolExecutor::dispatch`) and use it in
  `pending_tool_call`; fall back to a UUID only for prompts with no tool call
  (`/undo`, `/commit` confirmations), and send a final `tool_call_update` for
  those.

### A7 (Low) Tool-call titles and notices reach the editor without the approval escaping

- **Where:** `crates/aivyx-acp/src/translate.rs:218` (`ToolCallDetected`:
  `title` = the model's tool name, `raw_input` its arguments), `:182`
  (`Error`/`Warning` → `notice_paragraph`, including the injection notice's
  file excerpt), `:224` (tool output).
- **What happens:** approvals and plan entries now neutralise control, bidi
  and zero-width characters (C5/L3 fix), but the tool-call card title is the
  raw tool name from the model stream, which can be any string (an unknown
  tool still produces a card). A name like `read_file\u{202E}…\nApproved by
  user` is shown as-is. Display only: the call itself fails as an unknown
  tool and approvals are unaffected.
- **Proof:** `translate::tests::audit_a6_tool_call_title_neutralises_invisible_characters` (named before renumbering):
  `raw control/bidi characters in the tool-call title: "read_file\u{202e}\u{200b}\nApproved by user"`.
- **Fix direction:** pass the title (and notice text) through the shared
  escaping helper; consider titling cards from the gate's target text
  (`read_file src/main.rs`) rather than the bare tool name, which also gives
  Zed a useful label.

### A8 (Low) Client-supplied MCP servers are dropped without a word

- **Where:** `session.rs:602–679` (`req.mcp_servers` is never read).
- **What happens:** the spec says "All Agents MUST support [the stdio MCP]
  transport". Zed passes the user's configured context servers in
  `session/new`; coder ignores them and says nothing, so the user's MCP tools
  are silently missing. Ignoring them is the safe choice (nothing
  editor-supplied is spawned; see "Checked and clean"), but it should be
  visible.
- **Proof:** `check_client_mcp_servers_are_not_started` (a `touch` server
  left no marker); by reading for the silence.
- **Fix direction:** keep not spawning them by default; send a one-line
  start-up notice naming the ignored servers and how to add one to
  `config.toml` (where it is confined and approved). If support is added, run
  them through the same consent and `LandlockConfiner` as config servers.

### A9 (Low) "Always Deny" is offered but never remembered

- **Where:** `prompter.rs:53–58` (offers `reject_always`, labelled "Always
  Deny") and `:201–209` (maps it to a plain `Deny`; the gate never caches a
  refusal).
- **What happens:** a user who picks "Always Deny" is asked again at the next
  identical call. Fail-safe, but the label promises something that does not
  happen.
- **Fix direction:** drop the option, or label it plainly ("Deny"); a real
  deny cache keyed like Always-Allow is the alternative.

### A10 (Low) Registry coverage: two platforms, and Zed users stay on old fixes

- **Where:** `agent.json` (`darwin-aarch64`, `linux-x86_64` only).
- **What happens:** schema and archives are valid (both sha256s match the
  v0.6.4 assets; both `cmd` paths exist in the archives; `args: ["--acp"]`).
  Missing `linux-aarch64`, `darwin-x86_64`, `windows-*` produce only a
  registry warning, but those Zed users get no install at all, and the
  darwin build runs with `NoopConfiner` (documented). v0.6.4 is the latest
  release and the entry matches it, but the audit fixes on `main` (C5 approval
  escaping, C22 cancel) reach Zed users only with the next release plus A3's
  fix.
- **Fix direction:** add `aarch64-unknown-linux-musl` (Landlock works there)
  when convenient; release the Task 13 fixes.

## Not confirmed

- **The first-run path inside Zed.** By reading: with no `config.toml`,
  `initialize` advertises the terminal method `setup`, `session/new` fails
  `auth_required` (-32000, covered by `acp_e2e.rs`), Zed builds the terminal
  task from the agent's command with `args: ["--setup"]` and the env var
  (`first_class_terminal_auth_task`), and `--setup` wins over `--acp` in
  `main.rs`. Zed never calls `authenticate` for a terminal method (its v1
  `authenticate` refuses non-`agent` methods), so coder's missing
  `authenticate` handler (`-32601` in the probe) does not matter there.
  Whether Zed restarts the agent after the wizard (the wizard prints
  "Setup complete -- reconnecting...") was not seen live.
- **Cancel racing a permission request.** `AcpPrompter` waits on a
  `tokio::sync::Notify` woken by `notify_waiters`; a cancel that lands after
  the turn's last token check but before the `select!` first polls
  `notified()` would not wake it, leaving the C22 symptom for that one
  request. The window is microseconds; the C22 check below passes. Checking
  the turn's `CancellationToken` too (`token.cancelled()` in the `select!`)
  would close it.
- **Unsaved buffers.** coder reads and writes the disk directly and never uses
  the client's `fs/*` or `terminal/*` capabilities (it advertises none it
  needs). An edit to a file with unsaved changes in Zed will conflict with the
  buffer; Zed's own handling of that was not observed.
- **`cwd` as `/` or `$HOME`.** `session/new` accepts any existing directory,
  and the Landlock write grant follows it. This is the same as starting the TUI
  there (no ACP-only gap), but an editor makes it easier to do by accident
  (opening the home folder as a project).

## Checked and clean

- **stdout carries only JSON-RPC.** Tracing goes to `aivyx.log` in the config
  directory; every child process has `stdin` null or piped and its
  stdout/stderr piped or null (`run_shell`, `run_command`, git tools, MCP,
  LSP, `/test`, progress check, specialist enforcement; the REPL on a pty);
  the only `println!` paths (setup wizard, `pack` subcommands,
  `ask_mcp_consent`) are not reachable under `--acp`. Every line in all
  probes parsed as JSON. Malformed input gets `-32700 Parse error` and the
  connection stays usable; missing params get `-32602`; unknown methods
  (`authenticate`, `session/load`) get `-32601`; a second `session/new` is
  refused (one session per process, by design).
- **`session/load` and session-store traversal:** not advertised
  (`loadSession: false`) and not handled; `/resume` is not advertised over ACP.
  No session id from the client ever reaches the session store.
- **Client-supplied MCP servers:** never spawned (marker probe). Pack MCP
  servers need terminal consent, which `--acp` never has ("left off").
- **`cwd`:** canonicalised and required to be a directory; the agent is
  built for it after `session/new` (audit-4 A1 fix holds): sandbox write
  grant, checkpoints, sessions, `AGENTS.md`, packs, tests all follow it.
- **Gate parity:** the ACP session uses the same `ConfirmationGate` built by
  `build_agent`; `deny_paths` holds (`check_deny_paths_hold_over_acp`: a model
  `read_file` of `~/.ssh/id_canary` was hard-blocked, no permission request,
  canary text never reached the editor). `read_only_paths`, plan mode (via
  `session/set_mode`, checked before the Always-Allow cache), the
  outside-project note, the "runs code later" warning (and no Always Allow
  for those targets), and the one-off command rule all apply.
- **Approval text (C5 re-check):** the permission title is the full target
  (`display_command` / `escape_invisible`), never clipped; Write/Delete carry
  the full diff as ACP `Diff` content; previews are escaped; `raw_input` gives
  the program and arguments for `run_shell`.
- **"Allow always" binding:** maps to `UserResponse::AllowAlways`, cached by
  the gate on the exact target as in the TUI; unknown option ids and the
  `cancelled` outcome map to Deny.
- **Plan entries and commands:** plan text is escaped (control and invisible
  format characters; L3 fix); command names and descriptions are static.
- **Cancellation:** `check_cancel_mid_command` (approved `sleep 294`, then
  `session/cancel`: `stopReason: cancelled`, process gone) and
  `check_cancel_with_unanswered_permission` (C22 fix: a client that never
  answers the permission request, then cancels: `cancelled` at once, nothing
  ran).
- **stdin EOF:** coder exits and kills the running command (A1 control).
- **Release artefacts:** both v0.6.4 archives match the `agent.json` sha256s
  (`304d0058…` linux-musl, `bf1ca16c…` darwin), extract to the directories
  `cmd` names, and the entry validates against `agent.schema.json`
  (`license_url` present, `icon` left to the build). The fork's `agent.json`
  is byte-identical to the repo copy.

### `crates/aivyx/tests/acp_audit.rs`

Run: `CARGO_TARGET_DIR=<scratch> cargo test -p aivyx --test acp_audit -- --test-threads=1`.
Probe names map to finding IDs as follows: `audit_a1_*` → A1,
`audit_a2_*` → A2, `audit_a3_*` → A6, `audit_a4_*` → A4, `audit_a5_*` → A5; the unit probe `audit_a6_*` → A7.

```rust
//! ACP audit probes (2026-10-31). Drives the real `aivyx-coder --acp`
//! binary over stdio with raw JSON-RPC lines, the way Zed does, against a
//! wiremock model server. Every `audit_` test asserts the behaviour the spec
//! or the editor needs; a failing one is the proof of a finding.

use std::io::{BufRead, BufReader, Write};
use std::path::Path;
use std::process::{Child, ChildStdin, Command, Stdio};
use std::sync::atomic::{AtomicUsize, Ordering};
use std::sync::mpsc;
use std::time::{Duration, Instant};

use serde_json::{Value, json};
use wiremock::matchers::{method, path};
use wiremock::{Mock, MockServer, Request, Respond, ResponseTemplate};

fn sse(chunks: &[Value]) -> String {
    let mut body = String::new();
    for chunk in chunks {
        body.push_str(&format!("data: {chunk}\n\n"));
    }
    body.push_str("data: [DONE]\n\n");
    body
}

fn text_reply(text: &str) -> String {
    sse(&[
        json!({"choices": [{"delta": {"content": text}, "finish_reason": null}]}),
        json!({"choices": [{"delta": {}, "finish_reason": "stop"}]}),
    ])
}

fn tool_reply(id: &str, name: &str, arguments: Value) -> String {
    sse(&[
        json!({"choices": [{"delta": {"tool_calls": [{
            "index": 0, "id": id,
            "function": {"name": name, "arguments": arguments.to_string()}
        }]}, "finish_reason": null}]}),
        json!({"choices": [{"delta": {}, "finish_reason": "tool_calls"}]}),
    ])
}

/// Serves `replies` in order, then repeats the last one.
struct Sequence(Vec<String>, AtomicUsize);

impl Respond for Sequence {
    fn respond(&self, _: &Request) -> ResponseTemplate {

        let body = self.0[n.min(self.0.len() - 1)].clone();
        ResponseTemplate::new(200).set_body_raw(body, "text/event-stream")
    }
}

/// A running `aivyx-coder --acp`, in its own process group like Zed starts
/// it (Zed: `set_pre_exec_to_start_new_session`, then `killpg(SIGKILL)`).
struct Acp {
    child: Child,
    stdin: Option<ChildStdin>,
    rx: mpsc::Receiver<String>,
    /// Every line sent (`-> `) and received (`<- `), for the report.
    log: Vec<String>,
    next_id: u64,
}

impl Acp {
    fn start(home: &Path, project: &Path, tmpdir: Option<&Path>) -> Acp {
        use std::os::unix::process::CommandExt;
        let mut cmd = Command::new(env!("CARGO_BIN_EXE_aivyx-coder"));
        cmd.env("HOME", home)
            .env("XDG_CONFIG_HOME", home.join("config"))
            .env("XDG_DATA_HOME", home.join("data"))
            .env("XDG_STATE_HOME", home.join("state"))
            .env("XDG_CACHE_HOME", home.join("cache"))
            .current_dir(project)
            .arg("--acp")
            .process_group(0)
            .stdin(Stdio::piped())
            .stdout(Stdio::piped())
            .stderr(Stdio::null());
        if let Some(tmp) = tmpdir {
            cmd.env("TMPDIR", tmp);
        }
        let mut child = cmd.spawn().unwrap();
        let stdin = child.stdin.take();
        let stdout = child.stdout.take().unwrap();
        let (tx, rx) = mpsc::channel();
        std::thread::spawn(move || {
            for line in BufReader::new(stdout).lines() {
                let Ok(line) = line else { break };
                if tx.send(line).is_err() {
                    break;
                }
            }
        });
        Acp { child, stdin, rx, log: Vec::new(), next_id: 1 }
    }

    fn send_raw(&mut self, line: &str) {
        self.log.push(format!("-> {line}"));
        let stdin = self.stdin.as_mut().unwrap();
        stdin.write_all(line.as_bytes()).unwrap();
        stdin.write_all(b"\n").unwrap();
        stdin.flush().unwrap();
    }

    fn request(&mut self, method: &str, params: Value) -> u64 {
        let id = self.next_id;
        self.next_id += 1;
        self.send_raw(&json!({"jsonrpc": "2.0", "id": id, "method": method, "params": params}).to_string());
        id
    }

    fn notify(&mut self, method: &str, params: Value) {
        self.send_raw(&json!({"jsonrpc": "2.0", "method": method, "params": params}).to_string());
    }

    /// The next message from the agent. Panics if a line is not JSON (stdout
    /// must carry nothing but JSON-RPC).
    fn next(&mut self, timeout: Duration) -> Option<Value> {
        let line = self.rx.recv_timeout(timeout).ok()?;
        self.log.push(format!("<- {line}"));
        Some(serde_json::from_str(&line).unwrap_or_else(|e| panic!("non-JSON on stdout ({e}): {line}")))
    }

    /// Reads until the response to `id`, answering every permission request
    /// with `option` (when given) and keeping every message seen.
    fn until_response(&mut self, id: u64, option: Option<&str>, timeout: Duration) -> (Value, Vec<Value>) {
        let deadline = Instant::now() + timeout;
        let mut seen = Vec::new();
        loop {
            let left = deadline.saturating_duration_since(Instant::now());
            let msg = self.next(left).unwrap_or_else(|| panic!("no response to {id}; log:\n{}", self.log.join("\n")));
            if msg["id"] == json!(id) && msg.get("method").is_none() {
                return (msg, seen);
            }
            if msg["method"] == "session/request_permission"
                && let Some(option) = option
            {
                let reply = json!({"jsonrpc": "2.0", "id": msg["id"], "result": {
                    "outcome": {"outcome": "selected", "optionId": option}}});
                self.send_raw(&reply.to_string());
            }
            seen.push(msg);
        }
    }

    fn initialize(&mut self, version: u64) -> Value {
        let id = self.request("initialize", json!({"protocolVersion": version, "clientCapabilities": {
            "fs": {"readTextFile": true, "writeTextFile": true}, "terminal": true}}));
        self.until_response(id, None, Duration::from_secs(10)).0
    }

    fn new_session(&mut self, cwd: &Path, mcp: Value) -> String {
        let id = self.request("session/new", json!({"cwd": cwd, "mcpServers": mcp}));
        let (resp, _) = self.until_response(id, None, Duration::from_secs(30));
        resp["result"]["sessionId"].as_str().unwrap_or_else(|| panic!("{resp}")).to_string()
    }

    fn kill_group(&mut self) {
        let pgid = self.child.id();
        let _ = Command::new("kill").args(["-KILL", "--", &format!("-{pgid}")]).status();
        let _ = self.child.wait();
    }
}

impl Drop for Acp {
    fn drop(&mut self) {
        let _ = self.child.kill();
        let _ = self.child.wait();
    }
}

fn pids_matching(pattern: &str) -> Vec<String> {
    let out = Command::new("pgrep").args(["-f", pattern]).output().unwrap();
    String::from_utf8_lossy(&out.stdout).lines().map(str::to_string).collect()
}

fn wait_for_pids(pattern: &str, timeout: Duration) -> Vec<String> {
    let deadline = Instant::now() + timeout;
    while Instant::now() < deadline {
        let pids = pids_matching(pattern);
        if !pids.is_empty() {
            return pids;
        }
        std::thread::sleep(Duration::from_millis(100));
    }
    Vec::new()
}

fn kill_matching(pattern: &str) {
    let _ = Command::new("pkill").args(["-KILL", "-f", pattern]).status();
}

/// Starts a prompt whose model reply runs `sleep <secs>` through run_shell,
/// approves it, and returns once the command is running.
async fn running_command(secs: &str, tmpdir: Option<&Path>) -> (Acp, MockServer, tempfile::TempDir, tempfile::TempDir) {
    let server = model_server(vec![
        tool_reply("call_sleep", "run_shell", json!({"command": format!("sleep {secs}")})),
        text_reply("done"),
    ])
    .await;
    let (home, project) = setup(&server);
    let mut acp = Acp::start(home.path(), project.path(), tmpdir);
    acp.initialize(1);
    let sid = acp.new_session(project.path(), json!([]));
    let id = acp.request("session/prompt", json!({"sessionId": sid, "prompt": [{"type": "text", "text": "sleep"}]}));
    // Answer the permission request, then stop reading (the turn keeps running).
    let deadline = Instant::now() + Duration::from_secs(30);
    loop {
        let msg = acp.next(deadline.saturating_duration_since(Instant::now())).expect("permission request");
        if msg["method"] == "session/request_permission" {
            acp.send_raw(&json!({"jsonrpc": "2.0", "id": msg["id"], "result": {
                "outcome": {"outcome": "selected", "optionId": "allow_once"}}}).to_string());
            break;
        }
        assert_ne!(msg["id"], json!(id), "turn ended early: {msg}");
    }
    let pattern = format!("^sleep {secs}$");
    assert!(!wait_for_pids(&pattern, Duration::from_secs(15)).is_empty(), "sleep never started:\n{}", acp.log.join("\n"));
    (acp, server, home, project)
}
```
